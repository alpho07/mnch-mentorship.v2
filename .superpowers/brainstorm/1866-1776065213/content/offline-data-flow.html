Offline-First Data Architecture

Every new module follows the same offline-first pattern as assessments. IndexedDB stores are extended, not replaced. The sync queue gets new operation types.

Read Flow — All data types (GET requests)

App requests data
→
api.service.js
→
Network request
✓
Cache in IndexedDB
→
Return to UI
↓
Network fails / offline
Return cached data
→
UI works normally

Applies to: mentorships list, classes, modules, sessions, participant roster, my enrolled classes, module progress, global trainings

Write Flow — Actions (POST requests)

User takes action
→
Update local state
→
Try network
✓
Confirm
↓
Offline
Enqueue in SyncQueue
→
Optimistic UI shown
↓
Back online
Replay queued ops
→
Sync indicator clears

Applies to: module start/complete, attendance marking, mentee self-confirm attendance
