# Assessment Analytics Dashboard — Design Spec
**Date:** 2026-05-11  
**Branch:** feature/scope-redesign  
**Status:** Approved

---

## Overview

Add `mode=assessment` as the **first tab** on the existing `/analytics/dashboard` page (currently Training | Mentorship). When active it shows a comprehensive manager-level assessment analytics view including KPI cards, charts, insights, and a powerful facilities readiness table with mentorship eligibility scoring. A mentorship drill-down page is added for facility-level depth. Feedback tracking is managed via a new Filament backend action on the AssessmentResource.

---

## Scope

### In scope
- New `mode=assessment` on `/analytics/dashboard` (extend existing controller + blade)
- `AssessmentAnalyticsService` with all query logic
- Database migration: 4 feedback columns on `assessments`
- KPI strip (5 cards), 4 analytics charts, insights panel
- Facilities Readiness power table (read-only feedback status)
- "Mark Feedback Given" Filament action on `AssessmentResource` (backend only)
- Mentorship drill-down page at `/analytics/dashboard/facility/{facility}/mentorship-breakdown`

### Out of scope
- Changes to assessment data entry (EditSkillsLab, EditInfrastructure, etc.)
- Mobile API changes
- Exporting the power table to CSV/PDF (future)

## Section 1: Data Layer

### Migration — `add_feedback_tracking_to_assessments_table`
```
assessments table additions:
  feedback_given          boolean  default false
  feedback_given_by       FK → users  nullable, nullOnDelete
  feedback_given_at       timestamp   nullable
  feedback_notes          text        nullable
```

### Skills Lab Detection
Derived at query time — **no new stored column**.

```
has_skills_lab = exists(
  assessment_section_scores
    JOIN assessment_sections ON code = 'skills_lab'
  WHERE assessment_id = latest completed assessment for facility
    AND percentage > 0
)
```

If the skills_lab section was never completed (not in section_progress) or its score is 0, the facility is treated as having no skills lab.

### Eligibility Logic (computed per row in service)

| Condition | Status |
|---|---|
| assessed + skills_lab score > 0 + `feedback_given = true` | **Eligible** |
| assessed + skills_lab score > 0 + `feedback_given = false` | **Partially Eligible** |
| assessed + skills_lab score = 0 or section not completed | **Not Eligible** |

### New Service: `app/Services/AssessmentAnalyticsService`

Four public methods:

```php
getSummaryStats(array $filters): array
getChartData(array $filters): array
getFacilitiesReadiness(array $filters): Collection
generateInsights(array $stats): array
```

Filters shape: `['year' => string, 'county_id' => int|null, 'assessment_type' => string|null]`

The service queries the `assessments` table joined with:
- `facilities → subcounties → counties`
- `assessment_section_scores → assessment_sections`
- `facility_levels`
- `users` (for assessor + feedback_given_by)

## Section 2: KPI Strip & Charts

### KPI Strip (5 cards, replaces training/mentorship KPIs when mode=assessment)

| # | Label | Value Source | Trend |
|---|---|---|---|
| 1 | Total Assessments | `COUNT(assessments)` | YoY change |
| 2 | Facilities Assessed | `COUNT(DISTINCT facility_id)` | % of all facilities |
| 3 | Avg Score | `AVG(overall_percentage)` on completed | grade color |
| 4 | Have Skills Lab | facilities where skills_lab score > 0 | % of assessed |
| 5 | Eligible for Mentorship | facilities fully eligible | breakdown count |

### Charts (4 panels)

**Row 1:**
- **(2/3) Assessments Over Time** — 12-month grouped bar chart, grouped by `assessment_type` (baseline=teal, midline=amber, endline=violet)
- **(1/3) Grade Distribution** — donut chart, Green / Yellow / Red from `overall_grade` on completed assessments

**Row 2:**
- **(1/2) Section Score Averages** — horizontal bar chart, avg `percentage` per section (6 bars). Color: ≥80% green, 50–79% amber, <50% red. Immediately surfaces weakest sections nationally.
- **(1/2) Assessment Status Breakdown** — donut or grouped bar, draft / in_progress / completed counts with baseline/midline/endline split

### Insights Panel (4 cards, same card style as existing dashboard)

Auto-generated by `generateInsights()`:
1. Coverage: "X% of all facilities have been assessed"
2. Skills lab gap: "Y facilities assessed but lack a skills lab — not eligible for mentorship"
3. Feedback backlog: "Z facilities have skills lab but feedback not given — partially eligible"
4. Score leader: "Top scoring county: [name] at [X]% avg"

## Section 3: Facilities Readiness Power Table

Located below the charts on the assessment mode dashboard. Full-width card.

### Columns

| Column | Source | Display |
|---|---|---|
| Facility | `facilities.name` + `mfl_code` | Name bold, MFL code as small badge |
| Subcounty / County | `subcounties.name` / `counties.name` | Two-line cell |
| Level | `facility_levels.name` | Badge |
| Latest Assessment | `assessment_date` + `assessment_type` | Date + type badge |
| Assessed By | `assessor_name` | Plain text |
| Skills Lab | Derived from section scores | ✅ Yes / ❌ No badge |
| Feedback | `feedback_given` + `feedback_given_by.name` + `feedback_given_at` | "Given by X — May 3" or "⏳ Pending" |
| Eligibility | Computed | 🟢 Eligible / 🟡 Partial / 🔴 Not Eligible |
| Mentorships | COUNT of facility_mentorship trainings | Clickable number → drill-down |

### Table Filters (inline row above table)
- County (select, populated from DB)
- Skills Lab: All / Yes / No
- Eligibility: All / Eligible / Partial / Not Eligible
- Feedback: All / Given / Pending
- Assessment Type: All / Baseline / Midline / Endline

Table filter state is handled via URL query params or Alpine.js reactive filtering (consistent with existing dashboard pattern).

### Read-only feedback display
The feedback column is **display-only** on the analytics dashboard. No inline action button. Data entry for feedback is managed exclusively in the Filament admin backend.

## Section 4: Filament Backend — "Mark Feedback Given" Action

**File:** `app/Filament/Resources/AssessmentResource.php`

### Action placement
Inside the existing `ActionGroup` in the table, positioned **just below** "View Summary".

### Visibility rule
```php
->visible(fn($record) => $record->status === 'completed')
```

### Action behaviour
- Opens a **confirmation modal** (not a simple confirm — uses `form()` to collect `feedback_notes`)
- Modal fields: `Textarea::make('feedback_notes')->label('Feedback notes (optional)')`
- On confirm: sets `feedback_given = true`, `feedback_given_by = auth()->id()`, `feedback_given_at = now()`, saves `feedback_notes`
- Shows success Filament notification
- If feedback already given, action label changes to "Update Feedback" and pre-fills existing notes

### Model updates (`Assessment.php`)
- Add `feedback_given`, `feedback_given_by`, `feedback_given_at`, `feedback_notes` to `$fillable`
- Add relationship: `feedbackGivenBy(): BelongsTo → User`
- Add cast: `feedback_given => 'boolean'`, `feedback_given_at => 'datetime'`

## Section 5: Mentorship Drill-Down Page

### Route
```
GET /analytics/dashboard/facility/{facility}/mentorship-breakdown
```
New method: `AnalyticsDashboardController::facilityMentorshipBreakdown()`

### Breadcrumbs
`Analytics Dashboard → Assessment → {Facility Name} Mentorships`

### Page structure
One collapsible block per `Training` (type=facility_mentorship) at the facility.

**Program header:**
Program name | Status badge | Mentor name | Start date

**Per MentorshipClass row:**

| Column | Source |
|---|---|
| Class name | `mentorship_classes.name` |
| Period | `start_date → end_date` |
| Class status | badge |
| Modules | count of `class_modules` |
| Mentees | count of `class_participants` |
| Attendance | present / total from `session_attendance` |
| Sessions | count of `class_sessions` |

**Mentee roster (inline expand per class):**
Mentee name | Cadre | Department | Modules completed | Attendance status | Class status

### Data loading
Query pattern mirrors existing `facilityMentorships()` + `getParticipantsForProgram()` but eager-loads:
```php
Training::with([
    'mentor',
    'mentorshipClasses.classModules.programModule',
    'mentorshipClasses.classModules.attendanceRecords',
    'mentorshipClasses.classSessions',
    'mentorshipClasses.participants.user.cadre',
    'mentorshipClasses.participants.user.department',
])
```

## Key Design Decisions

1. **Skills lab derived, not stored** — avoids schema drift between the dynamic question responses and a boolean field. If section score > 0 it means real infrastructure was recorded.

2. **Feedback action backend-only** — keeps the analytics dashboard read-only and prevents accidental marking from the reporting view.

3. **Eligibility computed, not cached** — changes to feedback status immediately reflect in the table without a recompute job.

4. **Service layer isolation** — `AssessmentAnalyticsService` mirrors `TrainingAnalyticsService`. All complex SQL lives there; the controller is thin.

5. **Drill-down page not modal** — the mentorship breakdown is a full page (same design system) to accommodate the nested table depth (program → class → module → mentee roster).
