# Filament Admin — Design Polish + PWA Install

Date: 2026-08-19

## Goal

The Filament admin panel (`/admin`) should feel as polished as `public/m-assessment-app`
(the React/Capacitor mobile app) — smooth transitions, consistent rounded buttons/inputs/
checkboxes/toggles, nicer chart styling — and should be installable as an app on mobile and
desktop via the browser's native "Add to Home Screen" / "Install app" flow (PWA), without
adopting m-assessment-app's exact color palette or becoming a native-wrapped app.

## Non-goals

- Not copying m-assessment-app's purple/DM Sans palette — the panel keeps its existing
  navy/teal "Clinical Theme" identity.
- Not building offline data access. The service worker only makes the shell installable;
  admin data always requires network. No IndexedDB, no sync queue.
- Not touching the public resource frontend, `m-assessment-app`, or any panel other than
  `admin` (`/admin`).
- Not wrapping the panel in Capacitor/native shell.

## Current state

- `app/Providers/Filament/AdminPanelProvider.php` already injects
  `public/css/filament-admin-theme.css` via `renderHook(PanelsRenderHook::HEAD_END, ...)`
  with a `filemtime()` cache-busting query string. This file (781 lines) implements the
  navy sidebar gradient, Inter font, and teal/amber/emerald/violet accent system.
- `resources/css/theme.css` (built through Vite/Tailwind) adds `@apply`-based overrides for
  Filament form components (wizard steps, radio groups, sections, badges, tables).
- No manifest, service worker, or install affordance exists anywhere in the Laravel app today.
- Charts are standard Filament `ChartWidget` subclasses (Chart.js under the hood) — e.g.
  `ParticipantsByCadreChartWidget`, `TrainingsByMonthChartWidget`.
- `public/moh_logo.png` is a wide horizontal lockup (Kenya coat-of-arms + "MINISTRY OF
  HEALTH" wordmark) — not square, unsuitable to use directly as an app icon.

## Design

### 1. Design polish layer (CSS-only, plus a small PHP helper for charts)

Add a design-tokens block at the top of `public/css/filament-admin-theme.css`:

```css
:root {
  --mnch-radius-sm: 0.5rem;
  --mnch-radius-md: 0.75rem;
  --mnch-radius-lg: 1rem;
  --mnch-shadow-sm: 0 2px 8px rgba(15, 23, 42, 0.08);
  --mnch-shadow-md: 0 8px 24px rgba(15, 23, 42, 0.12);
  --mnch-transition: all 0.2s ease;
}
```

These tokens are then applied consistently (extending, not replacing, what already exists)
to:

- **Buttons** — all `fi-btn-*` variants get radius/shadow/hover-lift, not just
  primary/success/warning as today.
- **Inputs/selects/textareas** — consistent border radius, focus ring, and transition on
  `fi-input`, `fi-select`.
- **Checkboxes** (`fi-checkbox`) — custom rounded checkbox with a check-mark draw-in
  animation on check, replacing the browser-default box.
- **Toggles** (`fi-fo-toggle`) — smooth thumb-slide transition and accent fill color.
- **Cards / sections / stat widgets** (`fi-section`, `fi-wi-stats-overview-stat`) —
  consistent radius + shadow + hover lift, matching the existing `fi-in-entry-wrp` pattern.
- **Tables** (`fi-ta-table`) — header and pagination control polish, extending the existing
  row-hover treatment.

**Charts** can't be restyled by CSS alone (canvas is JS-rendered). Add
`app/Support/ChartTheme.php` with a static method returning a shared Chart.js options array
(soft gridlines, rounded bar corners, the existing teal/amber/emerald/violet accent palette,
smooth entrance animation). Each `*ChartWidget::getOptions()` merges this in:

```php
protected function getOptions(): array
{
    return array_merge(ChartTheme::base(), [
        // widget-specific overrides
    ]);
}
```

A thin CSS wrapper around the chart canvas container gets the same card radius/shadow as
other cards, so the chart doesn't look visually inconsistent with the polished cards around it.

All of this is edits to two existing files plus one new small PHP helper — no new build step,
no Livewire/Blade component changes.

### 2. PWA install layer (new static files + render-hook additions)

New files:

- `public/manifest.webmanifest` — `name: "MNCH Mentorship Admin"`, `display: "standalone"`,
  `start_url: "/admin"`, `scope: "/admin/"`, `theme_color`/`background_color` matched to the
  sidebar navy (`#1C3A8A`), icons at 192×192 and 512×512 (regular + one `purpose: "maskable"`
  variant).
- `public/icons/admin-icon-192.png`, `public/icons/admin-icon-512.png`,
  `public/icons/admin-icon-maskable-512.png` — generated by cropping the Kenya coat-of-arms
  crest out of `public/moh_logo.png` and placing it centered on a square navy (`#1C3A8A`)
  background (safe-area padding for the maskable variant per PWA maskable-icon spec).
- `public/sw.js` — precaches only static assets: the theme CSS, panel JS bundle, manifest,
  and icons. No HTML page caching, no API caching, no runtime cache of admin data. Registered
  with `scope: '/admin/'`.

Changes to `AdminPanelProvider.php`:

- Extend the existing `HEAD_END` render hook to also emit:
  `<link rel="manifest" href="...">`, `<meta name="theme-color" content="#1C3A8A">`,
  `<link rel="apple-touch-icon" href="...">`, `<meta name="apple-mobile-web-app-capable"
  content="yes">`.
- Add a small inline script (same hook, or a new `BODY_END` hook) that registers the service
  worker, guarded by `if ('serviceWorker' in navigator)`, scoped to `/admin/`.

Install affordance:

- Add an "Install App" item to the existing `userMenuItems()` list in `AdminPanelProvider`
  (next to "My Profile"), implemented as a small Alpine.js component that:
  - Listens for `window.beforeinstallprompt`, stores the event, shows the menu item, and
    calls `.prompt()` on click (Chrome/Edge/Android).
  - On iOS Safari (`beforeinstallprompt` never fires), shows a short instructional tooltip
    ("Tap Share → Add to Home Screen") instead of a functional button.
  - Hides itself entirely if the app is already running in standalone display mode
    (`window.matchMedia('(display-mode: standalone)')`).

### Data flow / error handling

No new data flow — this is presentation-layer only. Failure modes and handling:

- Service worker registration failure (unsupported browser, HTTPS unavailable in local dev)
  is caught and silently no-ops; the panel functions identically without it since nothing
  depends on the SW being active.
- If icon files are missing/fail to generate, the manifest still validates (browsers fall
  back to a generic icon) — install still works, just with a default icon.
- `beforeinstallprompt` not firing (already-installed, unsupported browser) simply keeps the
  "Install App" menu item hidden — no error state to handle.

  Lighthouse PWA audit passes "installable" checks.
- Manual: verify install flow on Android Chrome (native prompt) and desktop Chrome/Edge
